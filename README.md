# Crow × Alpine.js

## Обмен

- Глобальный `std::atomic<int64_t>` начинается с 0 при каждом запуске EXE.
- `GET /data/counter.json` возвращает `{"counter":0}` с `Cache-Control: no-store`.
  Страница выполняет fetch сразу при загрузке и затем каждые 2 секунды по умолчанию.
  Кнопки −/+ меняют интервал с шагом 1 секунду (минимум 1 с).
  Пауза останавливает новые запросы; уже отправленный завершается.
  Старт сразу запрашивает значение и возобновляет таймер. Изменение интервала на паузе не запускает опрос.
  Пока предыдущий fetch не завершён, новый пропускается; тайм-аут — 5 секунд.
- `/ws` принимает текстовые команды `increment_counter_value` и `get_counter_value`.
  Первая увеличивает atomic без ответа, вторая возвращает тот же формат JSON.
- Increment последовательно отправляет обе команды через одно WS-соединение.
  UI не прибавляет число самостоятельно: обновляет его только ответ сервера.
- При подключении WS также отправляется `get_counter_value`. При обрыве соединения
  кнопка отключается, переподключение выполняется через 2 секунды; HTTP продолжает работать.
- Ответ HTTP, начатый до уже полученного WS-ответа, не применяется, чтобы запоздавший
  снимок не заменял более новое значение. Его текст всё равно попадает в журнал.

## Реактивность и журнал

Alpine `x-text` связан с одним свойством `counter`. Присваивание происходит только
при изменении числа. Журнал показывает HTTP-запросы и полный текст ответов,
отправленные WS-команды, полученный WS JSON и ошибки.
Встроенный браузерный `MutationObserver` наблюдает только за узлом числа и фиксирует
реальное изменение текста DOM (а не физическую отрисовку пикселей браузером).
Одинаковые значения не создают события DOM; обновление самого журнала не считается
изменением счётчика. Хранятся последние 200 записей, новые сверху.
